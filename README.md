# Proofy — реестр проверенных достижений школьников

Gambit Hackathon 2026 трек HackHub кейс «Талант до вуза»

**Одной фразой:** организатор конкурса выдаёт сертификат с QR-кодом, а вуз или образовательное агентство за 5 секунд проверяет, что он настоящий — и чего стоит сам конкурс.

## Описание

Proofy решает проблему доверия. Грамоты легко подделать или купить, а платный онлайн-конкурс выглядит так же, как областная олимпиада. Proofy делает достижения школьников проверяемыми:

- **Сертификат создаёт только организатор** — он загружает список призёров, каждый получает ID вида `PRF-GH26-0001` и QR-код. Сертификат подписывается ECDSA-ключом (P-256) организатора; открыть ключ лежит в публичном реестре.
- **Проверка — публичная и мгновенная** (`#/verify` или камера): сервис сверяет ID с реестром и криптографически перепроверяет подпись. Поддельный сертификат, подменённый результат или чужой ключ не пройдут.
- **Вес конкурса (0–100)** считается по открытой формуле: уровень (20–85) + число участников (до +15) + отборочный этап (+10) − неподтверждённый организатор (−30) − платное участие без отбора (−25) − награждено больше 50% (−20).
- **Баллы за достижение** = вес × коэффициент результата (победитель 1,0 · призёр 0,7 · финалист 0,4 · участник 0,15).
- **Поиск талантов** — только с согласия школьника и родителя, без имени и контакта, пока школьник сам не одобрил запрос.

Роли в системе:

| Роль | Что делает | Что видит |
| --- | --- | --- |
| Школьник | управляет согласием, резюме, портфолио; отвечает на запросы | свой кабинет, **каталог конкурсов, организаторов и вузов** |
| Организатор | создаёт конкурсы, выдаёт подписанные сертификаты, ищет талантов | свой кабинет, **поиск талантов** (как у вуза), каталог вузов |
| Вуз / агентство | ищет таланты, просит контакт, проверяет сертификаты | поиск талантов, резюме, свои запросы |

## Возможности

- **Проверка сертификата** по ID или QR (камера / демо-скан): настоящий, подделка, изменённый результат, «платный конкурс» — 4 демо-сценария на главной.
- **Личные кабинеты** (вход по логину/паролю или кнопки демо-входа): кабинет открывается только после входа и только в свой аккаунт.
- **Регистрация** трёх ролей: логин + пароль + профиль; новый организатор сразу получает собственную криптопару.
- **Каталог хакатонов** (`#/hackathons`) — публичная витрина соревнований с отбором; деталь конкурса (`#/k/{id}`) с разбивкой веса.
- **Рейтинг конкурсов** (`#/ranking`) — все конкурсы с весом и формулой.
- **Поиск талантов** для вузов и организаторов: фильтры (город, направление, вес), правила приватности, запрос контакта → одобрение школьником.
- **Резюме и портфолио школьника** — публичная ссылка (`#/p/{id}`), превью «Так вас видит вуз», навыки, подтверждённые достижения.
- **Каталоги между ролями**: школьник видит всех организаторов и вузы («Куда участвовать»), организатор — вузы, все — хакатоны.
- **Живой REST API** (`/v1/...`) с журналом запросов на странице `#/api`; RBAC: 401 без/с неверным токеном, 403 на чужие сущности.
- **Офлайн-режим**: если сервер не запущен, фронт имитирует API в браузере (localStorage) — сайт работает и без бэкенда.
- **Сброс демо-данных** — кнопкой на сайте или `POST /v1/reset`.
- Интерфейс на трёх языках (ru / kk / en), адаптив, сканер QR с камеры.

## Требование

| Компонент | Версия | Зачем |
| --- | --- | --- |
| Node.js | ≥ 18 (проверено на 26) | только для сервера; сборка не нужна, внешних зависимостей нет |
| Браузер | современный (Chrome / Firefox / Safari / Zen) | фронтенд; для сканера QR — камера и getUserMedia |
| Операционная система | macOS / Linux / Windows | любая |

Сторонние библиотеки фронтенда подгружаются с CDN: [qrcodejs 1.0.0](https://github.com/davidshimjs/qrcodejs) (MIT, генерация QR) и [jsQR 1.4.0](https://github.com/cozmo/jsQR) (Apache-2.0, распознавание QR).

## Инструкция по запуску

### Вариант 1 — сайт + API одной командой (рекомендуется)

```bash
node server/server.js
```

Откройте <http://localhost:4173> — сервер отдаёт и сайт, и REST API. База создаётся автоматически (`server/data/db.json`, сид-данные: 4 организатора, 5 конкурсов, 6 школьников, 12 сертификатов, 2 вуза, 12 демо-аккаунтов).

### Вариант 2 — только сайт (офлайн, без сервера)

```bash
python3 -m http.server 5173
```

<http://localhost:5173> — все запросы обрабатываются в браузере, данные в `localStorage`.

### Демо-вход

На странице «Войти» (`#/login`) — кнопки демо-аккаунтов (пароль подставляется сам). Полный список — `GET /v1/accounts`. Примеры: `gambit` (организатор), `aigerim` (школьник), `bilim` (вуз).

### Тесты

```bash
cd server && npm test
```

38 смоук-тестов (`test.js`) + 174 строгих (`test.strict.js`): формы ответов, RBAC 401/403, правила согласия, жизненный цикл запросов, регистрация, формула веса, формат подписи, персистентность, WebCrypto-кросс-проверка «сервер → браузер».

### Настройки окружения

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `PORT` | `4173` | порт API + сайта |
| `HOST` | `0.0.0.0` | интерфейс |
| `CORS_ORIGIN` | `*` | допустимый origin фронтенда на другом хосте |

Сервер отдельно от сайта (фронт с другого хоста): `PORT=8080 CORS_ORIGIN=https://... node server/server.js`; во фронте адрес задаётся параметром `?api=http://host:port` (локально используется `http://localhost:4173` автоматически).

## Безопасность

**Криптография**
- Каждый сертификат подписан **ECDSA P-256** ключом организатора (подпись IEEE P1363, 64 байта r‖s). Открытые ключи — в публичном реестре (JWK + `kid`), закрытые — только в базе сервера.
- Проверка идёт криптографически: поддельный сертификат, изменённый результат или чужой ключ дают `sig_ok: false`. Та же проверка воспроизводится в браузере через WebCrypto (кросс-проверка в тестах).

**Доступ (RBAC)**
- Кабинеты открываются только после входа; ролевой срез `GET /v1/state` отдаёт **ровно собственные** данные роли. Чужая роль → 401, чужая сущность → 403.
- Выдача сертификатов и создание конкурсов — только организатор-владелец конкурса. Согласие и резюме меняет только владелец аккаунта. Ответ на запрос — только школьник.
- Токены: в демо пароль = Bearer-токен, в базе — только **SHA-256 хеш**, пароль в ответах API не возвращается.

**Данные несовершеннолетних**
- Профиль скрыт по умолчанию; в поиск попадает только при **согласии родителя** (в демо — тумблер с имитацией SMS-кода; при регистрации согласие не принимается — его можно дать только через кабинет).
- Имя, школу и контакт покупатель/организатор видит только после того, как школьник одобрил запрос; до этого — инициалы и класс.
- ИИН, телефон и фото не собираются. Все демо-данные тестовые.

**HTTP/сервер**
- Статика отдаётся только из корня; `server/` (база с закрытыми ключами), path traversal (`%2f`, `%2e%2e`) и закрытые поля JWK (`d`) не отдаются; на API-пути метод `POST` к статику → 405, неизвестный маршрут → 404 JSON.
- CORS настраивается через `CORS_ORIGIN`; журнал всех запросов — на сайте (`#/api`) и в консоли сервера.

**Ограничения прототипа (честно)**
- JSON-файл вместо PostgreSQL, сингл-инстанс, демо-токены в открытом виде — всё это сознательные упрощения прототипа; для рабочей версии см. [BACKEND.md](BACKEND.md).
- Демо-данные тестовые: никаких реальных персональных данных.
